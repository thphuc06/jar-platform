# P0.8: CI với GitHub Actions: pin SHA, quyền tối thiểu

> Ghi chú học tập của bước P0.8 (2026-10-23, commit `8acf0b2`). Kết quả và bối cảnh của bước nằm ở [roadmap](../06-plan/roadmap.md); quy ước 7 mục ở [README](README.md).

## Giải thích

- **Vì sao cần CI:** "máy tôi chạy được" chưa đủ. CI build trên một máy sạch ở mỗi lần push, nên lỗi do môi trường máy bạn (như vụ `JAVA_HOME`) sẽ lộ ra ngay.
- **Pin SHA cho action bên thứ ba:** một tag như `v3` có thể bị chủ repo, hoặc kẻ chiếm được repo, trỏ sang code khác. Commit SHA thì không đổi được. Đây là bài học từ vụ `tj-actions/changed-files` bị chiếm quyền năm 2025.
- **Quyền tối thiểu:** mặc định `GITHUB_TOKEN` có thể có quyền ghi. Đặt `contents: read` thì một bước bị chiếm cũng không sửa được repo.
- **Câu hỏi phỏng vấn:** *"Pipeline CI của bạn chặn được những loại lỗi nào trước khi merge?"* Trả lời: test hỏng, vi phạm ranh giới module, code chưa format, lộ secret.
- **Bài tập:** tạo branch thử, cố ý commit một chuỗi giống AWS access key (dạng `AKIA...` giả), mở PR, xem job `gitleaks` báo đỏ, rồi xóa branch đó.
