## 2. Tại sao
Từ P1 trở đi, mọi module đều cần DB. Bước này dựng 3 thứ nền:
- **schema được quản lý bằng code** (Flyway): mọi máy và mọi môi trường có cùng schema;
- **test chạy trên Postgres thật** chứ không phải DB giả;
- **dev chạy 1 lệnh**, không phải nhớ bật Docker trước.

## 3. Kiến thức cốt lõi
- **Flyway** lưu mỗi migration đã chạy vào bảng `flyway_schema_history`, kèm **checksum**. Lần chạy sau, nếu file V1 bị sửa thì checksum lệch và app **từ chối khởi động**. Migration đã áp dụng là bất biến; muốn đổi schema thì viết V2.
- **`@ServiceConnection`** dựa trên trừu tượng `ConnectionDetails` của Boot. Boot đọc host, port, user trực tiếp từ container, rồi **ghi đè** `spring.datasource.*`. Docker Compose support cũng dùng đúng cơ chế này, nên trong YAML không có URL hay password nào.
- **`@JdbcTest`** là test slice: chỉ nạp DataSource, `JdbcClient` và Flyway. Mỗi test chạy trong transaction rồi **rollback**, nên các test không làm bẩn dữ liệu của nhau. Phải có `replace = NONE`, nếu không Boot sẽ cố thay bằng DB nhúng (H2).
- **Unique trên `lower(email)`**: ràng buộc `UNIQUE (email)` thông thường coi `An@Mail.com` và `an@mail.com` là 2 người khác nhau. Expression index chặn được trường hợp này ngay ở tầng DB.

## 4. Cách khác & trade-off
| Cách | Trade-off |
|---|---|
| **H2 thay cho Testcontainers** | Nhanh, không cần Docker, nhưng "giả" Postgres: sai ở `TIMESTAMPTZ`, expression index, câu báo lỗi. Test xanh nhưng production vẫn có thể lỗi |
| **Liquibase** | Viết được migration bằng XML/YAML, có rollback; Flyway thì đơn giản, viết SQL thuần và phổ biến hơn trong JD Việt Nam |
| **JPA `ddl-auto=update`** | Tiện lúc demo, nhưng **không bao giờ dùng ở production**: không kiểm soát được, không có lịch sử, có thể làm mất dữ liệu |
| **Kiểu `citext` cho email** | Cần extension; expression index đủ dùng mà không phụ thuộc gì thêm |
| **Một container dùng chung cho mọi test (singleton)** | Hiện có 2 context nên chạy 2 container (khoảng 12 s). Tối ưu sau, khi số test tăng |

## 5. Lỗi hay gặp
- **Sửa file V1** sau khi đã chạy → `Validate failed: checksum mismatch`.
- **Dùng image `postgres:latest`** → mỗi lần pull có thể ra version khác.
- **Quên `@AutoConfigureTestDatabase(replace = NONE)`** → lỗi "no embedded database".
- **Docker Desktop chưa chạy** → Testcontainers báo *Could not find a valid Docker environment*.
- **Máy đã có Postgres cài sẵn chiếm cổng 5432** → compose không bind được port.
- **Không đặt schema**: bảng rơi vào `public`, lẫn với các thứ khác.

## 7. Bài tập nhỏ
1. Chạy `./mvnw spring-boot:run` một lần, rồi **sửa một ký tự** trong câu lệnh của `V1__baseline_users.sql` và chạy lại. Ghi lại thông báo lỗi và giải thích.
2. Đoán xem `flyway repair` làm gì, và vì sao **nguy hiểm** nếu dùng bừa.
3. **Hoàn tác thay đổi.** Sau đó viết migration `V2__users_locale_check.sql`, thêm `CHECK (locale IN ('vi-VN','en-US'))`, kèm một test chứng minh insert `locale='fr-FR'` bị từ chối.
